# gdocs-review-mcp — MVP plan (2026-07-13)

## Goal
MCP server letting a Claude instance work with Google Docs **comments** and
**edit suggestions** like a human reviewer. Requested by the client (they run
web pages from Google Docs with heavy comment/suggestion workflows).

Requirements (from requester, via Jonathan):
- Comments: replies, ~~reactions~~ (no API — descoped, documented), commented/quoted
  text; every object carries **id + author**.
- Suggestions: pre/post text, replies, id + author.
- Verbs: read, edit, write, create. Accept/reject for suggestions.
- Robust, reliable, low maintenance. No browser automation (sidecar explicitly skipped).

## Architecture decisions (settled in conversation, 2026-07-13)
- **REVISED 2026-07-13 (user directive): full Dev Preview API surface parity,
  autogenerated; based on taylorwilsdon/google_workspace_mcp (Python, ~3K stars).**
- Three layers:
  1. **Base**: fork of `taylorwilsdon/google_workspace_mcp` — OAuth 2.1 plumbing,
     service registration, existing Drive comment tools. Enable docs+drive only
     for the client deployment. Keep fork upstream-mergeable.
  2. **Generated layer**: MCP tools autogenerated from the Google API Discovery
     document for Docs v1 (incl. Dev Preview 2026-07-07 surface: anchored
     `InsertCommentRequest`, `writeMode: SUGGEST`, Accept/Reject/Delete
     suggestion, thread replies) + Drive v3 comments/replies. One tool per
     method AND per batchUpdate request-union member, params from discovery
     schemas. **Build-time generation, committed artifacts, CI drift job**
     (re-fetch discovery on schedule → regenerate → PR on diff). No runtime
     generation (silent auto-updates break e2e-tested surface).
  3. **Curated layer**: ergonomics the raw API lacks — `list_suggestions` with
     computed pre/post (view-mode diffing), `capabilities` probe, explicit
     `preview-required` errors. Additive, never replacing generated tools.
- Tool-count/context cost: generated layer is large → make it filterable via the
  upstream per-service/tool selection mechanism.
- OAuth user flow (acts as the authed user), token cached per upstream's scheme.
  No service accounts (comments must be authored as a real user).
- Reactions: **descoped** (no API surface anywhere; revisit only if the client insists →
  would require browser sidecar).
- Reference: research report
  `~/Repos/research-agent/reports/1ed5b6761c3341eb9c0af1ce9b90bbd6.md`.

## Tool surface (v1)
- `capabilities` — report GA vs preview feature availability for current creds.
- `read_document` — text + structure, optional `suggestionsViewMode`
  (inline / preview-accepted / preview-rejected).
- `list_comments` — all threads: id, author, content, quotedFileContent, resolved,
  replies[] (each: id, author, content), createdTime. Includes suggestion threads
  when API exposes them.
- `create_comment` — preview path: anchored (startIndex/endIndex); fallback:
  unanchored Drive comment (flagged in response).
- `reply_to_thread` — works for comment or suggestion threads (preview), Drive
  replies fallback for plain comments.
- `resolve_comment` / `delete_comment` / `update_comment`.
- `list_suggestions` — derived from documents.get: suggestion id, type
  (insert/delete/style), **pre/post text** (computed from the three view modes),
  author (NOTE: author exposure unverified — see Unknowns).
- `create_suggestion` — batchUpdate with SUGGEST write mode (preview).
- `accept_suggestion` / `reject_suggestion` (preview).
- `apply_edit` — direct (non-suggestion) batchUpdate edits, for the "edit" verb.
- `create_document` — for the "create" verb + e2e scratch docs.

## 2026-07-29 redirect: autogen layer removed
Owner directive: the raw Google API surface (one tool per method/request-union
member) is unfit for AI consumers. The autogenerated API-parity layer is
**removed** — codegen/, gdocs_preview/generated/, the discovery-drift CI job,
and their tests. The overlay's API knowledge (preview request types, SUGGEST
mechanics, response signals, permission rules, UNCERTAIN markers) is preserved
in `docs/preview-api-reference.md`. Hand-written native suggestion/comment
tools replace the generated surface — design note forthcoming in
`docs/plans/2026-07-14-native-integration.md`; e2e scenario modules
(test_ga_surface / test_preview_surface) are module-skipped pending that
retarget (redirect R4). Curated layer, service registration, scopes, and the
e2e harness core are unchanged.

Native tools implemented 2026-07-29 (R3, per the 2026-07-14 design note).
docs_preview service (7 tools): `list_document_suggestions`,
`get_doc_review_view`, `check_docs_review_capabilities` (renamed curated
trio), `suggest_doc_edit`, `manage_document_suggestion`,
`reply_to_doc_thread`, `create_anchored_doc_comment` (new write tools in
gdocs_preview/write_tools.py, all preview-gated through a shared
batchUpdate helper feeding preview_status). Factory extension:
`manage_document_comment` / `manage_spreadsheet_comment` /
`manage_presentation_comment` gained `update` and `delete` actions
(Drive v3 GA). e2e retarget remains with R4.
